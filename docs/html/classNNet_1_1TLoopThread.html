Detailed Description

template<typename TPoller>
class NNet::TLoopThread< TPoller >

A thread that runs its own event loop.

Owns a TLoop<TPoller> and a thread that runs it between Start() and Stop(). The poller is single-threaded, so it has one owner at a time:

  • until Start() and after Join() — the thread that owns the TLoopThread;
  • in between — the loop thread only.

Create the sockets, notifiers and coroutines of this poller before Start() and destroy them after Join(). While the loop runs, other threads reach its coroutines only through thread-safe objects: INotifier, TMpscQueue.

TLoopThread<TDefaultPoller> io;
TNotifier notifier(io.Poller());
TFuture<void> consumer = Consume(notifier, queue); // runs up to its first wait
io.Start();
...
io.Stop();
io.Join();
// consumer is destroyed here, before io

Stop() does not destroy coroutines: they stay suspended where they were and are destroyed by their owners after Join(). A stopped loop cannot be started again.

A poller closes a descriptor at its next poll, and after Join() there is none: sockets and notifiers destroyed after Join() stay open until the TLoopThread is destroyed, and only then does a peer see the end of its stream.

An exception that ends the loop (a poller throws std::system_error when its system call fails) does not terminate the process: Join() rethrows it. An owner that must learn of it at once, not at Join(), passes a failure hook to Start().

Starts the loop thread. Call once, from the owner thread.

Parameters
onFailureOptional. If the loop ends with an exception, it is called with that exception on the loop thread, before the thread exits; Join() still rethrows the exception. A loop that is stopped does not call it. It must not throw: an exception that leaves it terminates the process. Use it when the owner must act at once, for example to end a process that cannot work without this loop.

◆ Stop()

template<typename TPoller>
void NNet::TLoopThread< TPoller >::Stop ( )
inline

Asks the loop to exit. Any thread, any number of times, while the TLoopThread is alive: not concurrently with its destructor.

The loop exits after the step that sees the request, so a coroutine that never returns to the loop delays it. A request made before Start() is kept: the loop then makes one step and exits.
