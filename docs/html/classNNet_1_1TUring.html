Detailed Description

Poller implementation based on io_uring.

TUring inherits from TPollerBase and implements asynchronous I/O operations using the Linux io_uring API. It provides methods for performing asynchronous read, write, receive, send, accept, and connect operations.

Key features:

  • Uses io_uring to queue and submit asynchronous I/O operations.
  • Provides operations such as Read(), Write(), Recv(), Send(), Accept() and Connect().
  • Offers additional methods for cancelling pending operations, registering file descriptors, waiting for completions, and submitting queued requests.

Type aliases:

  • TSocket is defined as NNet::TPollerDrivenSocket<TUring>.
  • TFileHandle is defined as NNet::TPollerDrivenFileHandle<TUring>.

Example usage:

// Create an io_uring poller with a queue size of 256.
TUring uringPoller(256);
// Register a socket or file descriptor.
uringPoller.Register(socketFd);
// Post an asynchronous read. op must stay in place until it is delivered or cancelled.
TUring::TOperation op;
op.Handle = coroutineHandle;
uringPoller.Read(socketFd, buffer, bufferSize, op);
// Poll for I/O completions.
int ret = uringPoller.Wait();
// Resume the coroutines of the completed operations. The read's result is in op.Result.
uringPoller.WakeupReadyHandles();

◆ TOperation

using NNet::TUring::TOperation = NDetail::TOperationState

State of one operation, kept by the caller.

Set TOperation::Handle to the coroutine to resume before posting the operation; if posting throws, it is reset. The address of the state is the operation's user_data, so it must stay in place until WakeupReadyHandles() delivers the completion or Cancel() returns. The result of the completion is in TOperation::Result.

int NNet::TUring::Cancel ( TOperation & op)

Cancels a pending operation.

Called when the coroutine is destroyed while waiting for the operation. An operation not submitted yet is dropped. Otherwise it is cancelled, and the call returns only after the kernel has finished with it, so its buffers and op may be freed. Either way its completion is dropped, so its coroutine is not resumed. An operation that completed before the cancellation loses its result, e.g. the data it read.

Parameters
opState of the operation, not delivered yet.
Returns
The result of the dropped completion, e.g. a descriptor accepted meanwhile, or a negative value.
